# 時刻表を更新するときの手順

[← ドキュメント一覧（README）](../README.md) · [サイトの仕組み](architecture.md)

**目的：** 作者自身や変更を提案する人が、公式時刻表の更新に合わせてJSON・画面・PDF・検索用情報を**矛盾なく更新できる**ようにすることです。

## 作業全体の流れ

```text
公式資料を確認
   ↓
JSONの時刻・運行条件・出典を更新
   ↓
静的HTMLとPDFを再生成
   ↓
表示・運行日・印刷内容を確認
   ↓
変更をGitHubへ → Cloudflare Pagesで配信確認
   ↓
必要に応じてサイトマップ・Search Consoleを確認
```

> [!IMPORTANT]
> **JSONだけを変更して公開しないでください。** HTMLに埋め込まれた時刻表、JavaScript表示、配布PDFの内容が食い違う可能性があります。

## 1. 更新前の確認

- [ ] [小山市公式の路線・時刻表](https://www.city.oyama.tochigi.jp/o-bus/rosen-jikoku/page001803.html)で、高岳線・城東中久喜線・桑東部絹路線の資料と適用開始日を確認した。
- [ ] **改正日**と、個々の路線時刻表の**資料上の改正日**を区別した。
- [ ] 変更があった路線、停留所、運行条件（曜日・祝日・年末年始）、運賃案内への影響を整理した。
- [ ] 作業用ブランチを用意した。既存の本番ページに未確認の時刻を混ぜない。

編集の中心となるファイルはルートの `obus_2026_kosen.json` です。出典を追えるよう、`sources` に資料名・URL・適用日を残してください。

## 2. JSONを更新する

方向を取り違えないことが最重要です。

| キー | 意味 | 編集時に確認すること |
| --- | --- | --- |
| `S2K` | 小山駅東口 → 高専 | `display_time` は**駅の公式発車時刻** |
| `K2S` | 高専 → 小山駅東口 | `display_time` は**正門出発目安** |
| `stop_calls` | 公式の停留所時刻 | **参考値に書き換えない** |
| `college_stop_id` | 高専側の停留所 | 路線・便に合っているか |
| `walk_minutes` | 正門から停留所への徒歩補正 | 正門0分、入口6分、中久喜二丁目9分（現行値） |
| `calendar_id` | 運行日条件 | `calendars` 内に実在し、公式条件と一致するか |

帰りの目安時刻は原則として次の計算です。

```text
正門出発目安 = 公式の高専側停留所発車時刻 − 徒歩補正時分
```

**運行日を一括で「平日」にまとめないこと。** 現行JSONでは `joto_weekday`（祝日除外）と `kuwa_mon_fri`（祝日でも月～金なら運行、ただし12/29～1/3を除外）が別です。

確認すべき整合性：

- [ ] `segment_id` の重複がない。
- [ ] `physical_trip_id`、`route_id`、`calendar_id`、`source_id`、`college_stop_id` の参照関係が正しい。
- [ ] 公式時刻と徒歩補正から`display_time`を再計算して一致する。
- [ ] 各方向の時刻順・運行日・高専側停留所の選択が正しい。
- [ ] 2028年以降の利用や新年度への更新時は、`assets/js/departure.js` と `assets/js/watch.js` の祝日一覧も見直す（現状2026～2027年のみ）。

## 3. 静的HTMLを再生成

**必要環境：Node.js**

プロジェクトのルートで実行します。

```sh
node scripts/generate-timetables.mjs
```

生成対象は次の2ファイルです。

- `obus_2026_kosen_s2k.html`
- `obus_2026_kosen_k2s.html`

生成されるのはファイル内の**静的時刻表と凡例**です。これにより、JavaScriptが使えない環境や検索エンジンにも便情報が届きます。変更後はJSONと生成済みHTMLを**同じ変更セット**に含めてください。

## 4. PDFを再生成

**必要環境：Python 3、WeasyPrint、qrcode（Pillow）、日本語フォント。** 利用OSによってはWeasyPrintのネイティブ依存ライブラリも必要です。

Pythonパッケージの導入例：

```sh
python -m pip install "weasyprint>=68,<70" "qrcode[pil]>=8,<10"
python scripts/generate-pdfs.py
```

PDFの生成先：

- `obus_2026_kosen_s2k.pdf`
- `obus_2026_kosen_k2s.pdf`

**重要：** 現在のPDFスクリプトは便数を**往路52件・復路51件**と決め打ちで検査します。便数が変わる改正では、JSONを直すだけでなく**スクリプトの件数チェック、改正日の表示、固定文言も更新**してください。

> [!WARNING]
> `.github/workflows/build-pdfs.yml` のpushトリガーは、現状 **`feat/nitocbus-rebrand` ブランチ限定**です。**mainにpushすればPDFが自動更新される、と考えないでください。** ワークフローの対象ブランチを適切に見直すか、手動で生成・確認してください。手動起動用の `workflow_dispatch` は設定されています。

## 5. ローカル表示を確認

リポジトリのルートからローカルWebサーバーを起動します。

```sh
python -m http.server 8000
```

ブラウザで `http://localhost:8000/` を開き、最低限、次を点検してください。

- [ ] **行き・帰りの時刻表**：公式の駅発時刻・正門出発目安・路線番号・停留所・運行日記号を確認。
- [ ] **発車標**（`/departure/` と `/departure/k2s/`）：次の便と、帰りの徒歩補正を確認。
- [ ] **時計用画面**（`/watch/`）：方向切り替えと次の3便の表示を確認。
- [ ] **運行日**：平日・土日・祝日・年末年始で表示する便が正しいか確認。
- [ ] **PDF**：両方向がA4縦1枚に収まり、文字化け・欠け・誤時刻・QRリンク間違いがないか確認。
- [ ] **スマートフォン**：小さい画面で文字やボタンが重ならず、色以外でも区別できるか確認。
- [ ] **JavaScript無効時・JSON取得失敗時**：方向別の静的時刻表が残ることを確認。

`file://` でHTMLを直接開くとJSON取得が制限されることがあるため、ローカルサーバーを利用してください。

## 6. 公開と移転の確認

**公開先の設定URL：** <https://nitocbus.pages.dev/> 。Cloudflare Pagesの本番ブランチ・ビルド設定・デプロイ結果は、**Cloudflareダッシュボードで確認**してください。リポジトリの設定ファイルだけでは配信中の実状態は分かりません。

- [ ] 更新したJSON・HTML・PDFが同じリビジョンで公開されている。
- [ ] 主要ページ・PDFが正常に開け、`404.html` も機能する。
- [ ] `_headers`、`robots.txt`、`sitemap.xml` が意図した内容で配信されている。
- [ ] canonical・OGP・内部リンク・QRのURLが公開先と一致する。
- [ ] ページ内容を実際に変更した場合だけ、`sitemap.xml` の該当 `lastmod` を更新する（時刻表の改正日とは別）。
- [ ] 必要な場合、Search Consoleで新URLのページとサイトマップの状態を確認する。**sitemap.xml自体のインデックス登録リクエストは不要**。

### 旧URLからの移転

旧URLは `https://o-bus-kosen.pages.dev/` です。旧Pagesプロジェクト側の専用ブランチ `chore/legacy-301-redirect` の `_redirects` を利用する設計ですが、**Cloudflare側の本番ブランチ切り替えが必要**です。

新URLの公開確認 → 旧サイトの301転送設定 → HTML・PDFを含む転送確認、の順に進めます。**旧Pagesプロジェクトを先に削除しないでください。**

## 7. 不具合に遭遇したら

| 症状 | まず確認する場所 |
| --- | --- |
| 時刻表の時刻が古い | `obus_2026_kosen.json` とHTML再生成結果 |
| PDFの時刻が違う | `generate-pdfs.py` の実行結果・PDFコミット |
| 発車標や時計が古い | ページを再読み込み。初回取得JSONを保持する仕様 |
| 祝日に便が違う | `calendars` と各JSファイルの祝日一覧 |
| 一部の便が消える・増える | `calendar_id` の参照漏れ、条件判定 |
| ページが検索に出ない | canonical、robots、sitemap、Search Console |
| 旧URLから転送されない | **旧**Cloudflare Pagesプロジェクトの本番ブランチと `_redirects` |

現在のシステムには、JSON整合性・表示・PDFの**一括自動テストが十分に整っていません**。上記のチェックリストは省略せず、将来的には自動検査へ移行することを推奨します。

---

更新作業で迷った場合は、まず[データと画面の関係](architecture.md#データの読み方)を確認してください。**公式時刻**と**徒歩補正後の参考時刻**を分けて扱うことが、最も重要な原則です。
